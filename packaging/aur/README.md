# Rexon — AUR package (rexon-git)

Packaging files for Arch Linux / CachyOS / derivatives.
Author: Wehrwolfmann.

## Contents

| File | Purpose |
|---|---|
| `PKGBUILD` | -git variant: `pkgname=rexon-git`, `provides/conflicts=rexon` |
| `.SRCINFO` | generated by `makepkg --printsrcinfo` (regenerate on every PKGBUILD change!) |

The package has no static `.desktop` files: `rexon.desktop` and
`rexon-recover.desktop` are printed at build time by the core's generator
(`rust/rexon-core/src/bin/desktop-entry.rs`, `desktop-entry --package`) —
an entry point to the Rust window `/usr/lib/rexon/rexon-main-window`.
The `ярлыки_пакета_печатает_генератор_ядра` check in
`rust/rexon-core/tests/app_parity.rs` turns red if a static copy comes back
or the window's install path diverges from the core.

⚠️ **There is no Python in the package at all** (2026-09-16). `/usr/bin/rexon`
is an `sh` launcher for the Rust window; the package ships no interpreter,
no PySide6 and no `rexon_py` wheel. The polkit helpers and their policies
are printed at build time by a second core binary — `package-polkit`
(`rust/rexon-core/src/bin/package-polkit.rs`).

## What the package installs (differences from the built-in installer)

Rexon's built-in installer (core: `rust/rexon-core/src/installer.rs` —
decisions, `installer_exec.rs` — execution under pkexec) installs into
`/usr/local/lib/rexon`; the package uses **package** paths, without any
pkexec logic (pacman provides root):

- `/usr/lib/rexon/rexon/` — product DATA (not code): the vendored QML of the
  wallpaper tab with its translation catalog, `qt_wallpaper_engine/proto/UPSTREAM_TAG`,
  `kpackage/org.waywallen.kde` (the official waywallen-display release archive,
  unmodified, + our `vendor.toml`), `themes.json`, `assets/fonts`;
  next to it `/usr/lib/rexon/rexon_icon.png` — the tray icon (`tray::icon_candidates`);
- `/usr/lib/rexon/rexon-main-window` — the Rust window, the main entry point of the desktop entry (QML is baked into the binary);
- `/usr/bin/{rexon-wallpaper-host,rexon-splash-overlay}` — the wallpaper host (modes `--mode video|web`) and the login splash (the core looks for them in PATH);
- `/usr/lib/rexon/qml_modules/` — the QML module directory (the core looks for it as `qml_modules::SYSTEM_MODULE_DIRS`):
  - `Qcm/Material/libqml_materialplugin.so` + `libqml_material*.so` and `assets/` — styling of the vendored pages (QmlMaterial, MIT);
  - `waywallen/control/libwaywallen-controlplugin.so` + `libwaywallen-control.so` — Qt-Protobuf value types;
  - `waywallen/control/librexon_qt_filter.so` — the filter editor model (the QML tabs are built into `rexon-main-window`);
- `/usr/bin/rexon` — an `sh` launcher: `REXON_PACKAGED=1` + `exec /usr/lib/rexon/rexon-main-window "$@"`
  (the Rust window understands all product flags through the single door of the core, `cli::run_headless`);
- `/usr/lib/rexon-{de,pkg,stage,system}-helper` + `/usr/share/polkit-1/actions/org.rexon.*.policy` —
  privileged helpers and their policies (fewer password prompts: `auth_admin_keep` for 5 minutes,
  a confirmed `org.rexon.pkg` covers the other three actions);
- `/usr/lib/rexon-priv-helper` (a core binary, root 755) + `/usr/share/polkit-1/actions/org.rexon.session.policy` —
  the privilege session helper, "one password per launch": the window starts it with a single `pkexec`
  (`auth_admin` without keep, the helper itself holds the password while the window is open); the action
  is part of neither the "no password" rule nor anyone's `imply`. The file is taken from
  the build directory via `package-polkit --list-binaries` / `--path session`;
- `/usr/share/applications/{rexon,rexon-recover}.desktop` — printed by the core's generator at build time;
- `/usr/share/icons/hicolor/{16…512}/apps/rexon.png` (the new icon has no vector version) + `/usr/share/pixmaps/rexon.png`;
- `/usr/share/{gnome-shell,cinnamon}/extensions/rexon-wallpaper@rexon.app/` (+ compiled gschemas);
- `/usr/share/licenses/rexon-git/{LICENSE,NOTICE,LICENSE.QmlMaterial,LICENSE.NotoSans-OFL-1.1}`
  plus the machine translation engine: `LICENSE.fxtranslate-MPL-2.0`,
  `LICENSE.gemmology-MIT`, `LICENSE.xsimd-BSD-3-Clause` and
  `fxtranslate-0.4.2-rexon.patch` — our changes to the crate as a single file;
  installing it is what fulfills the per-file copyleft of MPL-2.0 (analysis:
  `rust/vendor/fxtranslate/ATTRIBUTION.md`).

Icon caches / desktop-database / sycoca are updated by **pacman hooks** — nothing needs to be done by hand.

### Packaged mode (REXON_PACKAGED)

The first-run wizard must not pop up for someone who installed the package.
There are TWO signals, and both are needed:

1. `REXON_PACKAGED=1` from the `/usr/bin/rexon` launcher — read by
   `installer::detect_default_mode` (`portable` mode) and `first_run_offer`
   (`FirstRunSkip::PackagedEnv`);
2. **the location of its own file** — the desktop entry calls
   `/usr/lib/rexon/rexon-main-window` directly, bypassing the `sh` launcher,
   so the variable is not set there. `installer::packaged_location`
   recognizes a package by the prefix `/usr/` (except `/usr/local/`),
   `/nix/store/` and `/app/` → `FirstRunSkip::PackagedLocation`.

The mode is chosen by the core; `prepare()` does not patch Rexon's sources.

### polkit helpers: why `/usr/lib` and not `/usr/local/lib`

A manual install puts the helpers into `/usr/local/lib` — a package must not
go there: Arch packaging rules forbid packages from writing to `/usr/local`,
and `pacman -R` would not remove such files. The core knows the path
(`system_plan::HELPER_DIRS`: package — `/usr/lib`, manual install —
`/usr/local/lib`) and chooses at run time by which file exists
(`de_helper_path` / `pkg_helper_path` / `stage_helper_path`). The policy
must `annotate` exactly the path the helper lives at — otherwise pkexec
will not pick our action and the password will be asked for EVERY
operation; that is why the XML is printed for the path
(`*_policy_xml_for`). The package does NOT install the passwordless rule
`/etc/polkit-1/rules.d/49-rexon-nopasswd.rules`: that is a separate choice
of the person.

## Local build / testing

```bash
# NOT in /tmp: it is a RAM-backed tmpfs, and the Rust build's target/ takes gigabytes
mkdir -p ~/rexon-pkgtest && cp PKGBUILD ~/rexon-pkgtest/
cd ~/rexon-pkgtest
makepkg --noarchive        # build only, no .pkg.tar.zst
makepkg -f                 # full package → pacman -U (at your own risk)
namcap PKGBUILD; namcap *.pkg.tar.zst   # lint (namcap package)
```

`source` points to the public repository. To build from your own clone:
`REXON_GITURL="git+file://<path to clone>" makepkg …` — only the
**committed** state is built, uncommitted changes do not get into the package.

### Variant with the bundled wallpaper engine (`REXON_BUNDLED_ENGINE=1`)

By default the wallpaper engine comes from the separate system packages
`waywallen` and `open-wallpaper-engine` (this is how the package goes to the
AUR and CachyOS). For the Steam release, manual installs and machines where
these packages are missing and you do not want to install them, the same
PKGBUILD builds a package with the engine inside:

```bash
REXON_BUNDLED_ENGINE=1 makepkg -f
```

What changes with `1` (with `0` or without the variable — nothing):

- `depends`: instead of `waywallen>=…` and `open-wallpaper-engine>=…` —
  `fuse3` (the AppImage runtime) and `at-spi2-core` (CEF inside the plugin);
- sources: the `waywallen-${_ww_ver}` AppImage, the waywallen MIT license,
  the OWE plugin release `${_owe_ver}`, the OWE git tag with its lito
  dependencies and the CEF archive (only the wrapper sources are taken from
  it) — with the same sha256 as before;
- `/usr/lib/rexon/engine/waywallen.AppImage` and
  `plugins/org.waywallen.open-wallpaper-engine/` — where the core looks for
  them (`we_client::ENGINE_DIR`);
- GPL-2.0-only §3(a): the complete OWE source of the same tag is assembled in
  `build()` and installed into `/usr/share/rexon/sources/`; the licenses of
  waywallen (MIT), OWE (GPL-2.0) and CEF (BSD-3-Clause) go into
  `/usr/share/licenses/rexon-git/`, and `GPL-2.0-only` is added to
  `license=()`. The notice is in `NOTICE`.

Such a package does not conflict with the `waywallen`/`open-wallpaper-engine`
packages: the bundled files live in their own directories. If both are
installed, the core starts the system engine and the bundle stays as a
fallback. Any value of the variable other than `0` and `1` is rejected by
`prepare()`. The protocol tag guard is the same for both variants:
`_ww_min` and (in the bundled one) `_ww_ver` must match
`proto/UPSTREAM_TAG`, `_owe_ver` must be no older than `_owe_min`.

`.SRCINFO` describes only the default variant (`makepkg --printsrcinfo`
without the variable): the AUR and helpers such as paru see the system
dependencies.

Why an environment variable rather than editing a line at the top of the
file: `REXON_GITURL` is passed the same way; the file in the repository and
`.SRCINFO` stay the default variant, and a "one-off" edit cannot be
committed by accident.

## Publishing to the AUR (once the public repository exists)

1. Check `_giturl` in `PKGBUILD` against the exact public URL
   (currently a placeholder `git+https://github.com/wehrwolfmann/rexon.git`, TODO),
   add `url=`.
2. (Preferably) create a `v5.0.0` git tag in the repository and simplify
   `pkgver()` to the `git describe --long --tags` variant
   (see the wiki: VCS package guidelines). There are no tags yet — the version
   is assembled as `<version from rust/Cargo.toml>.r<rev-count>.g<hash>`.
3. Create an AUR account and add an SSH key: https://aur.archlinux.org →
   My Account → SSH Public Key.
4. ```bash
   git clone ssh://aur@aur.archlinux.org/rexon-git.git aur-rexon-git
   cd aur-rexon-git
   cp /path/to/packaging/aur/PKGBUILD .
   makepkg --printsrcinfo > .SRCINFO     # REQUIRED on every push
   git add PKGBUILD .SRCINFO
   git commit -m "rexon-git 5.0.0.r37"
   git push
   ```
5. The stable (non -git) `rexon` package comes later: source = the release
   tarball with a fixed sha256, without `pkgver()`.

## Known limitations

- The package logically conflicts with an install made by the built-in
  installer in `/usr/local` (pacman does not see it) — before
  `pacman -U/-S`, remove it with Rexon's "Uninstall" or by hand.
- The package does not install autostart — the tray writes it at the person's choice.
- The `Qcm.Material` revision is recorded in the PKGBUILD twice — `_qm_pin`
  and the font checksums. `prepare()` fails if `_qm_pin` lags behind the
  vendored `QML_MATERIAL_PIN`; when changing the pin, recompute the sha256
  of the five fonts (`makepkg -g`) and update `.SRCINFO`.
- The wallpaper engine comes as separate packages (since 2026-10-30):
  `depends` on `waywallen>=${_ww_min}` and `open-wallpaper-engine>=${_owe_min}`;
  by default the Rexon package does not carry the AppImage, the OWE plugin
  or its sources (the bundled variant is `REXON_BUNDLED_ENGINE=1`, see
  "Local build"). Both packages are currently in the AUR (ZhangHua):
  `makepkg -s` will not fetch them — install them beforehand (`paru -S
  waywallen open-wallpaper-engine`). `waywallen-bin` does not satisfy the
  versioned dependency of `open-wallpaper-engine` (its `provides=waywallen`
  has no version). `_ww_min` must match `proto/UPSTREAM_TAG` — `prepare()`
  checks this; on a vendor bump raise it, check the plugin contract
  (`SUPPORTED_ENTRY_VERSIONS`, `SPAWN_VERSION`) and `_owe_min`, and update
  `.SRCINFO`; for the bundled variant also `_ww_ver`, `_owe_ver`, their
  sha256 (= the GitHub release `digest`), `_owe_git`/`_owe_reg` from the OWE
  tag's `lito.lock` and the lines in `NOTICE`. `_qm_pin` follows
  `QML_MATERIAL_PIN` after `scripts/rexon-vendor-update`.
- `xdg-terminal-exec` and `yay` in optdepends are AUR packages.
- `lito` in makedepends is an AUR package too (it is not in the official
  repositories): it builds the QExtra QML plugin. Before building, install
  `lito` or `lito-bin` (provides=lito), version 0.8.7 or newer — `makepkg -s`
  will not fetch it from the AUR by itself; a suitable binary from elsewhere
  can be given via the `LITO` variable (together with `makepkg -d`, since
  the dependency is not installed as a package). The build directory
  (`BUILDDIR`) must be an ASCII-only path — otherwise `prepare()` refuses.
  The QExtra sources (`_qe_git`, `_qe_reg`) must match
  `tools/qextra_plugin/lito.lock`; it is written by `scripts/rexon-vendor-update`.
- Any `makepkg.conf` flags will do (`-O2` on Arch, `-O3` on CachyOS, with or
  without `-g`): QExtra is built with lito's `release` profile, which
  controls optimization, debug info, LTO and strip itself — these flags and
  `_FORTIFY_SOURCE` are cut by `tools/build_qml_qextra.sh` from the flags
  passed to lito, while hardening flags (`-fstack-clash-protection`,
  `-fcf-protection`, `-D_GLIBCXX_ASSERTIONS`…) are kept.
- Memory. The build is parallel, and on a machine with 8 GB of RAM it was
  killed by OOM twice: `rustc` while linking and `cc1plus` on
  `control.qpb.cpp`. The job count is limited by `CARGO_BUILD_JOBS` (Rust)
  and `-jN` in `MAKEFLAGS` (`makepkg.conf`): from the latter `build()`
  derives `CMAKE_BUILD_PARALLEL_LEVEL` for `cmake --build` and lito's job
  count, unless they are set explicitly.
  With 8 GB this works:
  `CARGO_BUILD_JOBS=2 MAKEFLAGS=-j2 makepkg -f`.
