# Карта эталонов: что чем обновляется

Эталонов в дереве больше двух сотен, и до 07.09.2026 они обновлялись **четырьмя
разными способами**. Чем обновляется вот этот конкретный файл, приходилось
выяснять отдельным заходом — и это была одна из главных статей расхода при
обновлении вендора: приёмка waywallen 0.3.8 стоила ~13 часов, из них **четыре
коммита из шести чинили собственные леса**, а не принимали чужие изменения.

> ⛔ **02.10.2026: Python — только архив** (`_archived/`, метка git
> `python-final`). Генераторы на Python (`*_cases.py`, `frozen_*.py`), сверки
> моста `rexon_py` и съёмка кадров демона питоновским клиентом ушли туда же.
> Их эталоны остались в дереве ЗАМОРОЖЕННЫМИ и числятся в разделе 3 с этой
> причиной. Механизм пересъёмки остался у двух групп: `de_matrix` и
> `waywallen_qm`.

Теперь вход один:

```
scripts/rexon-golden-update --check     # ничего не пишет, говорит, что разошлось
scripts/rexon-golden-update             # обновляет всё и печатает дельту
scripts/rexon-golden-update --list      # эта же таблица, но из реестра прогона
```

> ⚠️ Таблица «с механизмом пересъёмки» ниже — human-редакция РЕЕСТРА внутри
> `scripts/rexon-golden-update`. Расходиться им негде: `--list` печатает реестр,
> а раздел «без механизма» прогон **вычисляет сам** — новый файл в
> `tests/golden/` попадает туда автоматически и не может
> притвориться проверенным.

## 1. Три рода эталонов — и почему это главное различие

| Род | Что значит | Что обязан сделать прогон без предпосылок |
|---|---|---|
| **код** | снимается с дерева, воспроизводится на любой машине | ничего — предпосылок не требует |
| **живое** | нужен инструмент системы (`lrelease`) | сказать **«НЕ ПРОВЕРЕНО»** и назвать причину |
| **руками** | механизма пересъёмки нет вовсе | перечислить поимённо с причиной |

⛔ **Тихий пропуск хуже отсутствия проверки.** 06.09.2026 сверка краснела
вдвойне, и второй дефект не был виден за первым. Поэтому сводка печатает все
три ведра ВСЕГДА, даже когда первое уже красное, а коды возврата различают
«разошлось» (1) и «не проверено» (3).

## 2. Эталоны с механизмом пересъёмки

| Эталон | Род | Чем обновлялся ДО | Чем обновляется ТЕПЕРЬ |
|---|---|---|---|
| `docs/de_customization_matrix.md` | код | `REXON_UPDATE_DOC=1 cargo test -p rexon-core --test de_customization` — команду знал только текст внутри самого документа | `scripts/rexon-golden-update de_matrix` |
| `data/qt_wallpaper_engine/qml_ui/waywallen_{ru,de}.qm` (по одному на каждый вендорный `.ts`) | **живое** | строка `lrelease …` из `docs/testing.md`, руками | `… waywallen_qm` |

### Что ушло из этой таблицы 02.10.2026 и почему

* `qt_main`, `qt_settings`, `qt_compare`, `qt_extensions` — генераторы
  `golden/*_cases.py` на Python (снимали замороженный исходник вкладок по
  хешу blob'а через `golden/frozen_source.py`). Генераторы — в
  `_archived/golden/rexon-core/`, сами `*_cases.json` заморожены. Менять их
  только осознанно и с объяснением, ЧТО в поведении изменилось.
* `bridge_refs` — эталоны сверок моста `rexon-py/tests/fixtures/*_reference.json`.
  Мост ушёл в `_archived/rexon-py/` целиком; два эталона, которые читают
  Rust-сверки, перенесены рядом с ними:
  `rexon-core/tests/golden/audio_capture_reference.json` и
  `rexon-gui/tests/golden/engine_update_reference.json` (заморожены).
* `we_live_frames` — кадры живого демона снимал питоновский клиент
  (`rexon.qt_wallpaper_engine.client` + `tools/we_proto`). Снимок
  `golden/we_live_frames.json` заморожен; переснять его можно будет, когда
  появится съёмщик на Rust.

### Отдельно: машинно-зависимые эталоны

Снимут на другой машине ДРУГОЕ, поэтому пересъёмка у них опаснее отсутствия
пересъёмки: `gtk_sanitizer_cases.json`, `installed_scan_tree.json`,
`favorites_real_names.json`, `local_preview_cases.json` (51 схема из
`/usr/share/color-schemes`), `scheme_look_cases.json` (цвета этих же схем
и стили Plasma машины, снятые программой на `KColorScheme`), `utils_cases.json`.
Образец беды — `qt_settings_parity.rs`: снимок живой машины развалил четыре
раздела при пересъёме в сентябре 2026, не поменяв ни строчки кода; лечение —
подставное дерево внутри генератора, оно там и стоит.

### Отдельно: НИЧЕЙ ЭТАЛОН

Файл лежит в `golden/`, выглядит эталоном и **не читается ни одной сверкой** —
при обновлении вендора это создаёт ложное чувство покрытия. Прогон ищет такие
сам и печатает в сводке. На 16.10.2026 таких нет.

Удалены: `rust_render_cases.json` — остаток снятого собственного рендерера
(09.10.2026); `remote_l10n_vendor_frozen.json` — замороженное дерево
waywallen v0.2.6+9 для паритета сборки `.ts` из своего словаря с Python;
словарь и сверка сняты 18.08.2026 (54ebb148), когда подписи вендорных
страниц стал переводить каталог самого waywallen (16.10.2026).

## 4. Что делать при обновлении вендора waywallen

Ничего из перечисленного руками — **есть одна команда**:

```
scripts/rexon-vendor-update v0.3.9           # принять новый тег
scripts/rexon-vendor-update --check v0.3.9   # только сказать, что разошлось
```

Она гонит девять шагов подряд — версии (вендор/апстрим), протокол, разметку
(+`qmldir`, +нашу патч-серию), QML-модули, оповещения моделей, каталог `.qm`,
`cargo build-app`, `cargo test-core` и `rexon-golden-update --check` — и печатает
ОДИН отчёт: что изменилось, что покраснело, что не собралось, что НЕ
ПРОВЕРЕНО. ⭐Она обязана дойти до конца: красный шаг не отменяет следующие,
иначе вторая поломка снова спрячется за первой.

⚠️ Последний шаг эталоны СВЕРЯЕТ, а не переснимает. Пересъёмка — отдельное,
осознанное действие по этой карте: `scripts/rexon-golden-update <группа>`,
и делать её надо, только понимая, ЧТО в поведении изменилось и почему это
правильно.

Что сохраняется вручную (порядок, если гнать шаги по одному):

1. вендорить `ui/qml` + `ui/i18n` (`scripts/sync-waywallen-*.py`);
2. `scripts/rexon-golden-update --check` — увидеть СРАЗУ весь список того, что
   разошлось, включая версию демона и новые роды событий;
3. `scripts/rexon-golden-update` — обновить и прочитать дельту по каждому файлу;
4. `cargo test-core` — принять результат.

Шаг 2 и есть главная экономия внутри этой карты: раньше расхождения вылезали
по одному, каждое — отдельным заходом «а чем обновляется вот этот».

## 5. Мерило — укус (проверено 07.09.2026)

> История: оба укуса ниже ставились на группы, которые 02.10.2026 ушли в
> архив вместе с Python (`qt_main`, `we_live_frames`). Принцип в силе для
> оставшихся групп.

Прогон, который не краснеет, ничего не проверяет. Поэтому по одному эталону
КАЖДОГО рода эталон портился точечно, и проверялось, что расхождение названо
поимённо.

**Род «код» — `golden/qt_main_cases.json`.** Испорчен один литерал
(`window.title`: «рабочих столов» → «рабочих СТОЛОВ»).
`--check` → `РАЗОШЁЛСЯ rust/rexon-core/tests/golden/qt_main_cases.json`,
дельта `полей: +0 −0 изменено 1 / ~ window.title`, код возврата **1**.
Обновление вернуло файл байт-в-байт к исходному, `--check` → **0**.

**Род «живое» — `golden/we_live_frames.json`.** Испорчены три места сразу:
`_daemon_version` 0.3.8 → 0.3.7, род payload у `tag_list` подменён на
`source_list`, ошибочный `autostart_get` выдан за успех.
`--check` назвал **все три** по отдельности плюс четвёртое, настоящее
расхождение (демон шлёт событие `playlist_changed`, которого в снимке нет),
код возврата **1**. Важно, что три укуса не спрятались друг за другом — это и
есть требование «второй дефект виден за первым».

**Ветка «НЕ ПРОВЕРЕНО».** Тот же прогон при недоступной сессионной шине
(`DBUS_SESSION_BUS_ADDRESS` на несуществующий сокет) не молчит и не зеленеет:
`НЕ ПРОВЕРЕНО: живой демон waywallen не отвечает … Поднять: systemctl --user
start rexon-wallpaper-engine`, код возврата **3**.

Заодно первая же настоящая пересъёмка кадров дала прирост покрытия: снимок
перестал держать `display_list` и `renderer_list` от версии 0.3.5 (там они
были сняты при не показывавшихся обоях) и получил шестой род push-события —
`playlist_changed`. `cargo test-core` на обновлённом снимке зелёный.
